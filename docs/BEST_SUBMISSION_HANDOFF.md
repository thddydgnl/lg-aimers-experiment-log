## 2. 문제와 학습 목표

목표는 각 투구 직전 정보로 `control_success = 1`일 확률을 예측하는 것이다. 평가는 Brier Skill Score이므로 단순 정답률보다 확률의 정확한 크기가 중요하다.

```text
Brier = mean((p_i - y_i)^2)
reference = r × (1 - r),  r = mean(y_i)
Score = max(0, 100000 × (1 - Brier / reference))
```

### 보조 outcome: `reverse_any`

공식 누적 카운트의 다음 행 변화로 과거 학습 행의 결과를 다음처럼 복원했다.

| 클래스 | 의미 |
| --- | --- |
| `success` | 제구 성공 |
| `reverse` | 요구 방향 반대 실패. reverse와 middle이 함께 증가한 경우도 포함 |
| `middle` | 가운데 몰림 실패 |
| `wide` | 어느 누적 카운트도 증가하지 않은 기타 실패 |

이 방식은 실패를 하나로 뭉개지 않고 실패의 형태를 구분한다. 추론 때는 다중분류 확률 중 `success` 확률만 최종 성공 확률로 사용한다. 라벨 복원은 과거 학습 시즌 안에서만 수행했고, 경계 행과 같이 다음 행 변화가 기계적으로 일관되지 않은 행은 제외했다. 최종 학습에는 전체 1,475,092행 중 1,474,300행이 사용됐다.

세 모델은 모두 같은 CatBoost MultiClass 설정을 사용했다.

| iterations | `500` |
| depth | `6` |
| learning rate | `0.05` |
| L2 regularization | `12.0` |
| random seed | `2026` |
| 학습 장치 | GPU |

공통 입력에는 경기 상황과 카운트, 좌·우타 및 좌·우투, 공식 누적 이력, 시즌 이전 투수 성공률, E14·platoon·타자 관련 통계, 주요 상호작용이 포함된다. raw `pitcher_id`는 최종 모델에서 제외해 새로운 투수에 대한 과적합 위험을 낮췄다.

### 세 구성원의 역할

| 모델 | 차별 정보 | 역할 | 2024 단독 점수 |
| --- | --- | --- | ---: |
| A | rich Trackman 전체 프로파일 + 투수 outcome component, K=120 | 가장 큰 비중의 주력 모델 | `908.1682` |
| C | rich Trackman 전체 프로파일, component 제외 | A의 component 의존 오차를 상쇄 | `924.8100` |
| B | Trackman/component 제외 + 과거 집단 성공률, K=500 | 물리 프로파일과 다른 집단 이력 신호 제공 | `908.7744` |

rich Trackman은 공식 2019~2024 정규경기 이력에서 투수별로 집계한 구속, 회전수, 수직·수평 무브먼트, 익스텐션, 릴리스 높이·측면, 존 통과 속도의 평균과 표준편차다. B의 집단 성공률은 다음 조합을 과거 완료 시즌에서만 계산해 K=500으로 평활했다.

- 경기 유형 × 월
- 경기 유형 × 볼카운트 × 스트라이크카운트
- 경기 유형 × 투수 손 × 타자 손
- 경기 유형 × 이닝

검증 시즌이 Y일 때 집계는 `season < Y`, 2025 추론용 집계는 `season <= 2024`만 사용했다. 테스트 데이터 전체의 평균·빈도·순서 정보는 사용하지 않았다.

### 앙상블과 보정

```text
p_raw = 0.50144385166253500 × p_A
      + 0.27016033407769313 × p_C
      + 0.22839581425977187 × p_B

p_final = clip(0.5 + 1.05 × (p_raw - 0.5) - 0.006,
               1e-6, 1 - 1e-6)
```

가중치는 0 이상이며 합이 1이다. affine 보정은 2024 OOF에서 고정된 작은 격자 안에서 선택했다. slope 1.05는 0.5 주변의 확률 차이를 조금 확대하고, offset -0.006은 전체 확률 수준을 소폭 낮춘다.

## 4. 왜 이 접근을 선택했는가

### 4.1 학습과 제출 recipe를 일치시켰다

이전 버전에서는 rolling 검증과 최종 제출의 iteration 수, 일부 feature와 early stopping 조건이 달랐다. V3에서는 모든 검증과 최종 학습을 500 iterations, 동일 feature, 동일 outcome 체계, 동일 seed로 고정해 검증 결과가 제출 모델을 더 직접적으로 설명하도록 했다.

### 4.2 실패 구조를 학습하는 편이 더 유용했다

`control_success`만 직접 맞히는 모델보다 `success/reverse/middle/wide`를 학습한 CatBoost 계열이 2024에서 더 좋은 신호를 보였다. 새 외부 라벨을 추가한 것이 아니라 공식 누적 카운트에서 이미 존재하는 실패 구조를 복원한 것이다.

### 4.3 단독 최고점보다 오차 다양성을 우선했다

C의 단독 점수가 가장 높았지만, A와 B를 함께 섞은 raw 앙상블은 2024 점수가 `937.7468`로 올라갔고 보정 후 `963.5501`까지 개선됐다. 이는 세 모델이 같은 행에서 항상 같은 방향으로 틀리지 않았음을 뜻한다. 최종 선택은 한 모델의 순위가 아니라 결합 Brier 손실을 기준으로 했다.

### 4.4 2023은 선택 fold로 쓰지 않았다

2023은 평가 체계 단절로 모든 후보 점수가 0이 되는 특수 구간이었다. 이 시즌은 기록만 남기고, 2024를 개발·선택 fold로, 2022를 안전성 확인 fold로 분리했다. 정보가 깨진 구간의 평균을 최적화 기준으로 삼지 않은 것이 핵심이다.

### 4.5 실패 실험도 선택 근거로 활용했다

XGBoost, CPU Ordered CatBoost, 기간차 감쇠, raw ID, Trackman 구종 군집, 여러 component 평활 강도는 최종 희소 앙상블보다 낮거나 실행 효율이 부족했다. 따라서 기능을 계속 늘리기보다 검증된 세 신호원만 남겼다.

## 7. 해석할 때 주의할 점

- 최고점은 단일 리더보드 관측값이다. 숨은 평가 데이터가 바뀌면 세 모델의 최적 가중치와 보정값도 달라질 수 있다.
- 2024는 모델 선택과 보정에 함께 사용됐으므로 bootstrap 구간은 탐색 편향까지 보정한 확증적 신뢰구간이 아니다.
- 2023 결과는 데이터·평가 체계 단절의 영향이 커 모델 품질 비교에 사용할 수 없다.
- rich Trackman은 투수 수준의 과거 프로파일이다. 경기 당일 구속 변화 같은 최신 상태를 직접 반영하지는 않는다.
- raw `pitcher_id`를 제외한 선택은 cold-start 안정성을 높이는 대신, 충분한 표본이 있는 특정 투수의 고유 효과를 일부 놓칠 수 있다.
- 예상 LB `1103.6977`은 실제보다 높았다. 이후 실험에서도 변환식의 절대값보다 후보 간 상대 순위를 중심으로 해석해야 한다.
